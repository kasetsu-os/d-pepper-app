# Dペッパー 安全点検チェックリスト（2026-10-12）

コード側の補強は `security/maintenance-2026-10` ブランチで実施済み。
ここに残っているのは、店長さんが各サービスの管理画面で確認・設定する項目です。

## A. 反映前に（Vercel）

- [ ] **独自ドメインを使っている場合**：環境変数 `ALLOWED_ORIGINS` にそのURLを入れる
      （例 `https://dpepper.example.jp`）。入れないと、そのドメインからの相談が「接続できませんでした」になる。
      `d-pepper-app.vercel.app` とプレビューURLは最初から許可済み。
- [ ] `URL_FETCH_ENABLED` は**入れない**（＝URL読み込み停止のまま）。

## B. 反映後すぐ（Vercel）

- [ ] 本番で通常相談・画像3枚つき相談・URLつき相談・履歴共有を各1件（deploy-policy の手順どおり）
- [ ] URLつき相談で「URLの内容までは確認できませんでしたが…」と出ることを確認（停止中の正常な動き）
- [ ] Firewall → レート制限ルールを追加：`/api/gemini` と `/api/share-history`、IPごと・1分あたり上限
      （コード内の制限はサーバーの台ごとに数えるため、こちらが本命）
- [ ] Settings → Billing：利用額の通知（Spend Management）を設定

## C. Google 側

- [ ] Gemini APIキーを発行したプロジェクトが **無料枠か有料（課金有効）か** を Google AI Studio で確認
      - 無料枠：送った相談文・画像がGoogleのサービス改善に使われ、人が見る可能性がある
      - 顔写真・頭皮の相談を扱うので、有料への切り替え、またはお客様への明示を検討
- [ ] APIキーに制限をかける（Google Cloud コンソール → 認証情報 → このキーは Generative Language API のみ）
- [ ] AI Studio で上限（クォータ）と、課金ありなら予算アラートを設定
- [ ] Googleフォーム：回答の閲覧・編集者が店長さん（と必要な人）だけか
- [ ] 回答先スプレッドシート：共有設定が「リンクを知っている全員」になっていないか
- [ ] 通知用 Apps Script：所有者と通知先メールが正しいか
- [ ] Googleアカウント・GitHub・Vercel に2段階認証が入っているか

## D. 次の改修候補（今回は見送り）

1. **AIへの指示文（プロンプト）をサーバー側で組み立てる**
   今はスマホ側で作った指示文をそのままAIに渡しているため、仕組みを知る人が
   `/api/gemini` を直接呼ぶと、Dペッパー以外の目的にもAPIを使えてしまう。
   お客様の文章とカテゴリだけ受け取り、ルール文はサーバーで足す形にすると根本的に塞がる。
2. URL読み込みを再開するなら：接続先のIPを名前解決後に確認する処理まで入れてから。
3. `src/App.jsx.bak` などの控えファイルをリポジトリから整理。
4. ブラウザの開発者画面に相談文・AI返答の一部を出している `console.log` の整理。
