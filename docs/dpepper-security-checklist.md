## 今回の修正が「できること」と「できないこと」

- **Origin確認**：他サイトのページから、お客様のブラウザ経由で呼ばれるのを制限する補助策。
  送信元情報は攻撃用プログラムで偽装できるため、**APIへの直接アクセスや不正利用を防ぐものではない。**
- **コード内の連続送信制限（1分6回など）**：Vercel の実行環境ごとのメモリで数える方式。
  実行環境が複数に増えるとアプリ全体の回数は保証できない。**最低限の歯止めであり、本番の制限は Vercel Firewall で行う。**
- **入力上限・エラー詳細の非公開・APIキーのヘッダー化**：コードで完結する対策。
- 第三者による利用で起こりうるのは、主に**AI利用枠・費用の消費**。APIキー本体の流出や、
  他のお客様の履歴の読み出し（履歴は各端末内に保存）が確認されたわけではない。

## C. Google 側（お客様の情報保護）

- [ ] **Gemini の扱いの確認方法**：Dペッパーが使うAPIキーのGoogle Cloudプロジェクトに、
      **有効な請求先アカウント（Cloud Billing）が関連付けられているか**を確認する。
      請求額が出ているかどうかではなく、この関連付けの有無で無料サービス／有料サービスの扱いが分かれる。
      - 無料サービス扱い：送信内容が改善に使われ、人が確認する可能性がある。
        Google の規約は、**無料サービスに機密・センシティブ・個人情報を送らないこと**を定めている。
      - **「お客様に説明する」は有料化の代わりにならない。** 説明すれば無料サービスに個人情報等を送ってよい、ではない。
      - したがって、どちらかが必要：
        1. 請求先アカウントを関連付けて有料サービス扱いにする
        2. 無料サービス扱いのまま使うなら、識別可能な顔写真・個人情報等を送らない設計・運用にする
           （具体的な運用方法は、Google の規約と照らして店長さんが判断する）
      - お客様への説明（何がどこに送られるか）は、上記とは別に行う
- [ ] APIキーに制限をかける（Google Cloud コンソール → 認証情報 → Generative Language API のみ）

- [ ] Googleフォーム：回答の閲覧・編集者が必要な人だけか
