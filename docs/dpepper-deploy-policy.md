# Dペッパー 本番更新ルール

最終更新：2026-06-13

Dペッパーはすでにお客様が触っているため、ルール追加や実装修正で本番利用者に大きな不具合を出さないよう、更新の安全基準を明文化します。

---

## 1. 更新種別

### 軽微変更（営業中でも対応可）

- `dpepperRules.js` のルール追加・文言調整
- `dpepperPrompt.js` のトリガー追加
- 分類調整
- テスト文追加

**条件：** `npm run build` と本番確認は必須。

---

### 注意変更（できれば営業時間外）

- 相談フォーム
- 画像添付
- URL添付
- 共有フォーム
- 履歴パネル
- 文字サイズ切替
- リクルート導線

---

### 重要変更（営業時間外推奨）

- `/api/gemini`
- Gemini retry 処理
- APIキー・Vercel環境変数
- 保存形式・ルーティング
- 外部連携

**条件：** 変更後は必ず本番で通常相談・必要に応じて画像/URL/リクルートを確認する。

---

## 2. 毎回の更新手順

1. `npm run build`
2. `git status` 確認
3. commit
4. push
5. Vercel deploy 完了確認
6. 本番URLで通常相談を1件送信
7. Vercel Logs で `POST 200 /api/gemini` を確認
8. エラーがあれば直すかロールバック判断

---

## 3. 本番確認項目

**通常相談（毎回）**
- 返答が出る
- `POST 200 /api/gemini` が出る
- `Gemini ok` がログに出る

**画像やURLを触った場合**
- 画像あり相談
- URLあり相談
- URL失敗時のログ（`URL unreadable` の表示）

**リクルートを触った場合**
- 「お店の雰囲気は？」で美容相談に流れないこと
- `mode:recruit` がログに出ること

---

## 4. 原則

- Dペッパーは「壊さず育てる」
- 機能追加より、相談のズレを減らすことを優先する
- 営業中は軽微なルール追加までに留める
- 大きな構造変更は営業時間外に行う
